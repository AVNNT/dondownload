DonDownload Capture

Settings

Capture stays explicit by default. Only settings you approve here change automatic behavior.

Overlay and capture

On a site where you enable the overlay, DonDownload may analyze the page with yt-dlp in the background when its player uses HLS, DASH or Media Source, so verified qualities are already there when you open the panel. It runs only on that exact enabled origin, at most once per settled page URL, and reuses the result until it expires. It never reads cookies, request headers or DRM data. Progressive files the player actually played stay one-click downloads.

Detected media

On a site where you enabled the overlay, DonDownload watches completed HTTP(S) responses through the optional webRequest permission and lists video/audio files, HLS and DASH manifests. It never reads request headers, bodies or DRM data. Range requests to the same file collapse to one row, HLS/DASH segments are hidden, and tiny or obvious ad/tracker responses are ignored. YouTube keeps using the yt-dlp page analysis because its range/SABR streams are not standalone files.

Cookies for detected media

Off by default for every site. When you turn this on for one exact origin, the extension reads that site's cookies for the media URL and sends them with one download job so login-protected media can work. The app passes them to aria2 or yt-dlp for that job only; they are never written to the extension's or app's settings, database or logs. Cookies can grant access to your account, so leave this off unless the site needs it.

    Automatic file hand-off

    Off until you approve the optional downloads permission. When enabled, the extension hands off only an HTTP(S) ordinary file (zip, PDF, installer and similar). Video/audio, manifests, segments, extension downloads and excluded sites are never touched. The browser download is cancelled only after DonDownload returns a durable receipt.

    Playback response evidence (optional)

    Off by default. This requests the optional webRequest permission only from the button below. It observes response status and only Content-Type, Content-Range, Content-Length and Content-Encoding for an exact media response in an opted-in top-frame page. It never reads cookies, credentials, request headers, bodies or DRM data. It does not make extra network requests; that permission alone does not read cookies. Without this evidence, an extensionless video/mp4 or video/webm source is not queued.

    Excluded sites

    Enter an exact origin, for example https://example.com. Downloads started on that exact origin are always left to the browser.
